\section{Metodología}
\subsection{Propuesta de solución}
\label{propuesta_solucion}
La solución propuesta consiste en desarrollar un sistema web desde cero siguiendo la arquitectura MVC con el framework ASP.NET Core (.NET 10), con persistencia de datos y almacenamiento en la nube. El sistema consta de dos módulos, el módulo de conversion y carga de archivos, que permite subir documentos en distintos formatos para su conversión a PDF, asi como imágenes y enlaces. Y el módulo de gestión documental, que permite ver todos los archivos almacenados en el sistema y generar codigos QR para cada uno de ellos, asi como la visualización, la eliminación o la descarga de los archivos, todo desde una misma plataforma.

El proceso de autenticación se integra con el mecanismo existente en la institucion, ya que esta plataforma solo sera accedida como una extensión de sistemas que ya tienen su proceso de autenticación.

\subsubsection{Beneficios del sistema propuesto}
Al implementar esta propuesta la gestión documental del PJETAM mejoraría en la accesibilidad de los documentos, sería más fácil el referenciar los documentos mediante su código QR ya sea digital o impreso, el sistema también facilita el proceso de almacenar los documentos en un mismo sitio, y hace los procedimientos más fáciles al hacerlo en la misma plataforma, quitando la necesidad de usar herramientas externas.

\subsubsection{Diagrama de Entidad-Relación de la Base de Datos}
El diagrama de entidad-relación de la Figura \ref{fig:modelo-er} corresponde al modelo utilizado para este sistema, la base de datos en SQL Server, consta de cinco entidades y sus relaciones entre sí. Todos los identificadores, que también son las llaves primarias, utilizan el tipo de dato ULID para mayor seguridad y para garantizar que el identificador sea único.

La entidad Area representa las áreas en las que se divide la institución, y a las cuales estan relacionados cada usuario o empleado, y asi organizar los archivos por área para facilitar su gestión posteriormente. Un Area puede tener múltiples usuarios y un usuario puede estar relacionado a múltiples archivos, la entidad Archivo registra todos los metadatos de los archivos subidos al sistema.

La entidad Usuario también se relaciona con la entidad Log\_acceso la cual se encarga de registrar todas las acciones realizadas por un usuario en el sistema.

\subsubsection{Diagramas de secuencia}

\paragraph{Proceso de Autenticación vía AuthToken}
La Figura \ref{fig:sec-autenticacion} es el diagrama de secuencia del proceso de autenticación del sistema, este proceso inicia cuando el usuario accede al sistema mediante un enlace ya predeterminado por la institución, que contiene el parámetro AuthToken, el cual contiene el nombre de usuario y la contraseña. Los archivos del sistema que interactuan son el archivo AuthMiddleware el cual detiene la petición y evalúa si existe una sesión activa o no, si no existe un sesión se ejecuta el archivo AuthService el cual se encarga de consultar la base de datos para verificar si ya existe un usuario con ese nombre para actualizar su último acceso, si no existe un usuario crea el área con el nombre de usuario y los vincula.
Una vez identificado el usuario, el Middleware guarda su identificador, nombre y área en la sesión del navegador, para que el sistema reconozca al usuario en todas las pantallas posteriores sin necesidad de repetir el proceso.

\subsection{Desarrollo del sistema}
\subsubsection{Arquitectura del sistema}
El sistema fue desarrollado utilizando el patrón de arquitectura Modelo-Vista-Controlador (MVC), implementado sobre el framework ASP.NET Core 10. La arquitectura MVC divide el sistema en tres módulos: el Modelo, que en este ssitema son las entidades de la base de datos, la Vista, que es todo con lo que el usuario interactua y ve, las interfaces de usuario fueron desarrolladas con archivos Razor (.cshtml), y el Controlador que es el intermediario entre las peticiones del usuario y los servicios del sistema.
Al utilizar la arquitectura MVC es más fácil darle mantenimiento y actualizar el sistema cuando sea necesario.

\subsubsection{Lenguajes de programación}
El sistema utiliza principalmente el lenguje C\# para el backend, esto para aprovechar las características disponibles en .NET 10, como lo son la programación asíncrona y el uso de System.Ulid para los identificadores utilizdos en el sistema.
Para las vistas se combina código \#C y HTML (.cshtml) para facilitar el contenido dinámico en el lado del servidor. El frontend utiliza HTML5, CSS3, Javascript, Bootstrap 5 y Bootstrap Icons para hacer la interfaz más atractiva visualmente y más fácil de usar.

\subsubsection{Herramientas de desarrollo}
El desarrollo del sistema se realizó utilizando Visual Studio Code como editor de código.
El sistema utiliza SQL Server 2022 como motor de base de datos relacional, para crearla se utilizó Entity Framework Core con el enfoque Code First, ya que para hacer las tablas del esquema se hicieron clases de C\# y para generar las tablas se utilizaron migraciones, para la administración y gestión de la base de datos se utilizó la extensión SQL Server (mssql) de Microsoft incluida en Visual Studio Code.

\subsubsection{Almacenamiento en la nube}
Para almacenar los archivos el sistema utiliza el servicio AWS S3 (Amazon Simple Storage Service), los archivos se organizan en el bucket dependiendo del tipo que sean. El sistema implementa S3 mediante el SDK oficial de AWS para .NET, y se utilizan los paquetes AWSSdk.Core y AWSSDK S3. El sistema y este servicio cumplen con los requisitos para tratar la información con seguridad.

\subsubsection{Bibliotecas y paquetes utilizados}
Para la conversión a PDF el sistema utiliza el servicio LibreOffice 7 en modo headless, llamado desde el código C\# como un proceso del sistema operativo. Mientras que para que la generación de códigos QR se utiliza la librería QRCoder, ajustada con el nivel Q de corrección de errores para lograr que sean útiles para documentos físicos que puedan sufrir daños.

Para los mensajes de confimarción o avisos del sistema se utiliza la biblioteca SweetAlert2 para hacer más fácil la interacción del usuario, ya que permite agregar iconos dependiendo del mensaje, haciendo que el usuario perciba el mensaje más facilmente.
